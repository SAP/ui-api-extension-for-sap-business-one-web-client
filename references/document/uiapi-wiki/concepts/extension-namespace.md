## Definition

SAP B1 Web Client UI API uses two distinct namespace systems: the **control namespace** (`b1.sdk`) for all public framework classes and types, and the **extension namespace** (provider + app + module) for isolating extensions from different partners.

## How it works

### Control namespace: `b1.sdk`

All framework controls and types live under `b1.sdk.*`. Examples:

- `b1.sdk.Button` — the Button control class
- `b1.sdk.ButtonType.Accept` — an enum value for the `buttonType` property

This is a global namespace shared by all extensions. Never define custom symbols under `b1.sdk`.

### Extension namespace: provider + app + module

Each extension has a three-part namespace:

```
namespace = provider name + app name + module name
```

This is automatically generated by the UIAPI creation wizard and stored in `manifest.json`. The wizard scaffolds a minimal project from templates — generating the manifest, overlay JSON, and controller files needed to get started (a working hello-world app). It appears in the overlay `controller` property path:

```
<provider>.<app>.<module>.controller.<controllerName>
```

## Why it matters

The extension namespace prevents code conflicts between multiple extensions from different partners running simultaneously on the same Web Client instance. The three-part structure ensures uniqueness even when different providers develop extensions for the same view.

## Tradeoffs and constraints

- The namespace is auto-generated — developers should not manually construct or alter it.
- Changes to provider/app/module names after initial setup may require updating all overlay file references.
